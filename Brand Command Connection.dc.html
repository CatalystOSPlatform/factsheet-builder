Connecting the Document Builder to Brand Command

Brand Command stays the single source of truth. The Builder only reads from it — and only when the user switches it on for a document.

1. How Data Flows

Source
Brand Command Center
Each client's brand is saved to the shared CatalystOS database as a read-only Brand Profile.
catalystos_brand_profiles / {client}
Bridge
Brand SDK
The same connector every CatalystOS app uses. Lists clients and fetches one brand profile. Falls back to the local cache if offline.
listClients()getBrandProfile()
Gate
User Opts In
Nothing is fetched until the user turns on Use Brand Command and picks a client. Off by default, per document.
Result
Document Builder
Brand values fill the header, footer and (optionally) text styles. Content is never overwritten. Saved with the document.
Read-only: the Builder never writes back to Brand Command.

4. Decisions Needed

Logos: Source of Truth ✓Brand Command already stores color, black and white logos. One line in its shared profile publishes them to every app.
Who Sees Which Clients?Today the list shows every client. Limiting by user needs sign-in on the Brand Command side.
Auto-Update or Manual?Proposed: manual Refresh Brand, so an approved document never changes on its own.
Prompt at New Project?Optionally ask "Use a Brand Command client?" in the Start a New Project window.
